# Переработка веб-интерфейса VKeen — дизайн

Дата: 2026-09-29. Статус: согласован в чате, ждёт ревью спецификации.

## 1. Зачем

Панелью пользуется в основном сам владелец роутера — опытный пользователь, примерно поровну
с компьютера и с телефона. Нужны все сценарии сразу: переключить сервер, убедиться что всё
работает (и какую страну видят сервисы), управлять маршрутами, разбираться «почему не
открывается», управлять подписками/ключами, устройствами и WireGuard.

Что сейчас мешает (из скриншотов и разбора кода):

- Серверы, подписки и ключи разнесены по трём вкладкам.
- Статус врёт: «Работает» рядом с «Xray не запущен» — три разных проверки процесса
  (`status`: pid-файл + `pgrep`; `check_ips`: только `pgrep -x`; `test_connection`: только
  pid-файл). BusyBox `pgrep -x xray` не находит процесс, запущенный как `/opt/sbin/xray run`.
- Выбранный сервер «откатывается»: id сервера подписки — md5 ссылки; когда провайдер меняет
  ссылку, выбор теряется, конфиг молча берёт другой сервер, а UI отмечает несуществующий.
- Логи — одна строка «Xray started»; ни событий, ни соединений, ни диагностики.
- Кнопка «Тест» выглядит как проверка сервера, а проверяет весь туннель.
- Технический долг UI: один файл `index.php` на 2100 строк, 59 inline `onclick` со строковой
  подстановкой (ломается на кавычках, риск инъекции), два вида переключателей и модалок,
  `prompt()`/`confirm()` для паролей и опасных действий, ошибки API часто игнорируются.

**Критерий успеха:** любую повседневную задачу можно сделать за 1–2 действия с главного экрана
или из очевидного раздела; статус никогда не противоречит сам себе; по любой проблеме
«почему не открывается X» есть ответ в «Диагностике» без SSH.

### Не цели

- Мультипользовательский режим, роли, i18n (интерфейс только на русском).
- Несовместимые изменения хранения правил, подписок и ключей (в файлах `/opt/etc/xray`
  допускаются только новые необязательные поля, чтобы работал откат на `legacy.php`).
- Замена Xray/AdGuard или механизма маршрутизации.

## 2. Ограничения среды

- Роутер Keenetic, MIPS (EN7528), 254 МБ ОЗУ, Entware, BusyBox, lighttpd + PHP 8 (без `ctype`).
- Внешние CDN недоступны надёжно (ТСПУ) — все ассеты локальные.
- Любая операция, перезапускающая Xray/AdGuard, дорогая (секунды CPU) — её нужно делать
  один раз на пользовательское действие.
- Интерфейс открывается из LAN без логина (как сейчас), извне — с сессией.

## 3. Технический подход

**Preact + htm без сборки.** В репозиторий кладётся `htm/preact/standalone.module.js`
(htm 3.1.1, включает Preact; ~13 КБ) как `src/web/ui/vendor/preact-htm.js`. Код — ES-модули,
которые роутер отдаёт как статику. Сборки, Node и CI-шагов не добавляется.

Отклонённые варианты: чистый JS на модулях (без компонентной модели при таком объёме снова
получится каша); Svelte/Vite (нужна сборка в релизе — лишнее для проекта на shell/PHP).

### Файлы

```
src/web/index.php            — оболочка: <html>, <link app.css>, <script type=module src=ui/app.js>
src/web/legacy.php           — текущий интерфейс без изменений (на один релиз)
src/web/ui/app.css           — токены темы, компоненты
src/web/ui/app.js            — корень: роутинг по hash, layout, опрос
src/web/ui/api.js            — обёртка fetch: единая обработка ошибок, тосты, 401 → логин
src/web/ui/store.js          — общее состояние (overview, серверы) + подписки компонентов
src/web/ui/components/*.js   — Button, Toggle, Modal/Sheet, Toast, Badge, Card, EmptyState,
                               ListRow, SearchInput, Tabs, Confirm
src/web/ui/screens/*.js      — overview, servers, routes, devices, diagnostics, settings,
                               login, wizard
src/web/ui/vendor/preact-htm.js
```

`manifest.template.json`/`manifest.json` получают записи для всех файлов `src/web/ui/**` и
`legacy.php`.

### Правила кода UI

- Никаких inline-обработчиков и сборки HTML строками — только htm-шаблоны (автоэкранирование).
- Все вызовы API через `api.js`: `{error}` в ответе → тост с текстом ошибки; сетевые ошибки →
  тост «роутер не отвечает»; 401 → экран логина.
- Опасные действия — модальное подтверждение с названием объекта, пароли — формы.
- Доступность: настоящие `<button>`, роли `tab`/`radio`/`switch`, фокус-ловушка и Esc в
  модалках, возврат фокуса, `aria-live` для тостов.
- Опрос только при видимой вкладке (Page Visibility): `overview` каждые 10 с, `check_ips`
  каждые 60 с и по требованию.

## 4. Структура интерфейса

Компьютер (≥ 900 px): боковое меню слева + контент. Телефон: нижняя навигация на 5 пунктов,
шестерёнка настроек в шапке, крупные цели касания (≥ 44 px), шторки снизу вместо модалок.

Разделы: **Обзор · Серверы · Маршруты · Устройства · Диагностика**, плюс **Настройки**.
Адреса через hash (`#/servers`, `#/diagnostics/connections`) — работает «назад» и закладки.

### 4.1 Обзор

- **Карточка состояния** — одно состояние из `overview.state`:
  `running` «Работает» / `paused` «Пауза: сервер недоступен» / `stopped` «Остановлен» /
  `config_error` «Ошибка конфига» (с текстом ошибки Xray) / `starting` «Запускается».
  Кнопки: Старт/Стоп (по `state`, а не по тексту карточки), Перезапуск.
- **Текущий сервер** — название, флаг, протокол, пинг; страна «для Google» и «для остальных»
  (последняя проверка, кнопка «проверить»). Кнопка **«Сменить сервер»** открывает шторку
  выбора (тот же список, что в «Серверах», с поиском и избранным сверху).
- **IP** — VPN IP и реальный IP.
- **Предупреждения** (из `overview.warnings`): подписка истекла; выбранный сервер пропал из
  подписки — «сейчас используется X» + кнопка выбрать; сервер недоступен (пауза watchdog);
  Google видит страну выхода как RU; обнаружены прямые соединения к VPN-адресам.
- **Последние события** — 5 последних из журнала, ссылка на «Диагностику».

### 4.2 Серверы

- Один список, сгруппированный по источникам: каждая подписка (название, число серверов,
  время обновления, последняя ошибка, кнопки «обновить», вкл/выкл, удалить) и «Мои ключи».
- Строка сервера: флаг/название, бейдж протокола, адрес, пинг, страна для Google (если
  проверялась), звезда «избранное»; активный выделен. **Без переключателя вкл/выкл у
  отдельных серверов** (решение владельца 2026-09-30): отключается только подписка целиком;
  ранее отключённые серверы показываются как обычные и включаются при выборе.
  Нажатие — выбрать сервер (с индикатором применения и результатом/ошибкой).
- Сверху: поиск, фильтры (протокол, страна, только избранные), кнопка «Проверить все»
  (пинг), кнопка **«Добавить»** — одно поле: `http(s)://…` → подписка, `vless://`, `ss://`,
  `hysteria2://`, `hy2://`, `trojan://` → ключ; можно вставить сразу несколько строк.
- Меню сервера: «Проверить страну», «Реальная задержка», «Копировать ссылку», для ключей —
  «Переименовать», «Удалить».

### 4.3 Маршруты

- **Сервисы** — каталог v2fly-списков и подключённых списков: переключатель + выбор цели
  (VPN-активный / конкретный сервер / напрямую). Поиск по каталогу v2fly.
- **Свои правила** — домены и IP: добавление (в т.ч. пачкой), режим (суффикс/точно), цель,
  массовое выделение и действия одним запросом, поиск, фильтры, «убрать дубли».
- **«Куда пойдёт…»** — поле: домен или IP → какое правило сработает, цель, в `vpn1` ли его IP.

### 4.4 Устройства

- Устройства сети (из Keenetic): имя, IP, MAC, онлайн; режим «Выборочно» / «Всё через VPN».
- WireGuard-клиенты: статус, handshake, трафик; добавить; конфиг (текст + QR-картинка SVG,
  генерируется на роутере `qrencode -t SVG`, с фолбэком на текущий UTF8), удалить.
  Раздел WireGuard скрыт, если функция выключена.

### 4.5 Диагностика

Каждая вкладка включается/выключается в «Настройки → Диагностика»; выключенная не видна и
не потребляет ресурсы.

1. **События** — журнал по-человечески, с фильтром по уровню и типу.
2. **Соединения** — живые соединения LAN: устройство, домен, IP:порт, протокол, маршрут
   (через какой сервер / напрямую / отклонён QUIC), подсветка «утечка» (адрес в `vpn1`, а
   идёт напрямую). Поиск по домену/устройству.
3. **Проверка сайта** — ввод домена → DNS через AdGuard, в `vpn1` ли, какое правило,
   через какой выход, страна глазами Google и Cloudflare через этот выход, есть ли прямые
   соединения и QUIC-утечки к нему.
4. **Сырые логи** — Xray error/access, AdGuard, manager/update; выбор числа строк,
   автообновление, подсветка уровней, «очистить».

### 4.6 Настройки (страница, не модалка)

- **Общие:** тема (авто/светлая/тёмная, авто следит за системой), версия.
- **Обновления:** проверка, «что нового», установка, откат (вместо колокольчика; в шапке —
  точка-индикатор, если есть обновление).
- **Диагностика:** переключатели «Журнал событий», «Соединения», «Проверка сайта»,
  «Сырые логи Xray» (= запись логов Xray).
- **Функции:** WireGuard, AdGuard, автообновление.
- **Безопасность:** пароль панели, пароль Keenetic — формы с проверкой.
- **Опасная зона:** откат обновления, повторный мастер настройки — с подтверждением.

## 5. Изменения API (`src/web/api.php`)

Существующие действия сохраняются (их использует `legacy.php`). Новые и изменённые:

| Действие | Что делает |
|---|---|
| `overview` (public read) | Состояние, активный и **фактический** сервер, причина, предупреждения, память, WG, признак обновления, версия. Дёшево: без сетевых запросов. |
| `check_ips` (изм.) | Использует общую `xray_running()`. |
| `servers` (public read) | Единый список: источники (подписки с метаданными + «ключи») и серверы с `id`, `name`, `proto`, `host`, `port`, `enabled`, `favorite`, `source`, кешем пинга и страны. |
| `add_link` | Автоопределение подписка/ключ, несколько строк за раз. |
| `set_server_flags` | Вкл/выкл, избранное для серверов подписки и ключей; применяет конфиг один раз. |
| `rename_key`, `toggle_subscription` | Как названо. |
| `ping_servers` | TCP-connect к `host:port` параллельно (для hysteria — `null`), кеш 5 мин. |
| `server_probe` | Временный Xray с socks `127.0.0.1:10899` для одного сервера: реальная задержка, выходной IP, страна для Google (`countryCode` YouTube) и Cloudflare (`/cdn-cgi/trace`). Один запуск одновременно (lock-файл), таймаут 25 с, кеш 1 ч. |
| `route_explain` | Домен/IP → сработавшее правило, цель, наличие IP в `vpn1`. Использует ту же логику bucket’ов, что и генератор конфига. |
| `rules_batch` | Массовые изменения правил (удалить/сменить цель/режим) с одним применением. |
| `events` | Последние N событий, фильтр по уровню/типу. |
| `connections` | Снимок `conntrack -L` для LAN + сопоставление с access.log Xray (outbound по `ip:port` клиента) + домены по IP из журнала AdGuard. |
| `site_check` | См. 4.5.3. |
| `logs` (изм.) | Источники: `xray_error`, `xray_access`, `adguard`, `manager`, `update`. |
| `set_features` (изм.) | Новые ключи `diag_events`, `diag_connections`, `diag_site_check`; `logs_enabled` без `kill -HUP` — через перезапуск Xray. |

### Серверная логика

- **`xray_running()`** — одна функция: `pidof xray`; используется в `status`, `overview`,
  `check_ips`, `test_connection`. `shell_run` не дописывает `2>&1` к командам, где stderr уже
  перенаправлен.
- **Устойчивый выбор сервера.** `state.json` хранит `active_outbound` (id) и
  `active_hint` (`name`, `host`, `port`, `proto`). После `update_subscriptions`, если id
  пропал, ищется сервер с тем же `name`+`proto`, затем `host`+`port`; найденный id
  записывается обратно. Генератор конфига пишет в `state.json` `effective_outbound` и
  `effective_reason` (`selected` / `fallback_missing` / `fallback_disabled` / `default`);
  `overview` показывает расхождение как предупреждение.
- **Применение изменений.** Все мутации идут через `apply_changes()` с `flock` на
  `/opt/var/run/xray-apply.lock`: второе одновременное применение ждёт первое, а не
  запускает параллельный перезапуск. `toggle_key`, `toggle_github_list`,
  `update_subscriptions` применяют конфиг.
- **Журнал событий** — `/opt/var/log/xray-vpn/events.log`, JSON Lines:
  `{"ts":"ISO8601","level":"info|warn|error","type":"server|service|rules|subscription|watchdog|config|update|firewall","msg":"текст по-русски","data":{}}`.
  Пишут `api.php` (`emit_event()`) и `xray-manager.sh` (watchdog пауза/возобновление,
  ошибка старта, `_kick_leaked_flows` с числом сброшенных соединений). Ротация при 256 КБ,
  хранится один предыдущий файл. Выключенный `diag_events` → запись не делается.
- **Домены для соединений.** Журнал AdGuard (`querylog.json`) хранит ответ DNS в
  wire-формате base64; PHP-функция декодирует A/AAAA-записи. Читаются последние 2 МБ,
  строится карта IP → домен (последний по времени).

## 6. Обработка ошибок

- Любой `{error}` из API показывается пользователю; действия с применением конфига
  возвращают итог (`ok`, `xray_running`, текст ошибки Xray при провале `-test`).
- Если конфиг не проходит `xray run -test`, старый конфиг не заменяется, Xray остаётся на
  старом, событие `config` уровня `error` с текстом Xray, `overview.state = config_error`.
- Проверки с сетью (`server_probe`, `site_check`, `ping_servers`) имеют таймауты и
  возвращают частичный результат с пометкой, что не удалось.

## 7. Тестирование

- `tests/php/` — php-cli скрипты без фреймворка для чистых функций: парсеры ссылок,
  определение подписка/ключ, сопоставление пропавшего сервера, `route_explain`, декодер
  DNS wire-формата, разбор `conntrack`/access.log.
- `tests/docker` + `tests/smoke.sh` — новые действия отвечают JSON, `overview.state`
  согласован с `xray_running()` (в т.ч. при запуске Xray с полным путём).
- Ручная проверка на роутере: чек-лист всех экранов на компьютере и телефоне, со
  скриншотами; чек-лист паритета с `legacy.php` (каждая функция старого UI есть в новом).

## 8. Этапы

1. **Фундамент API:** `xray_running()`, `overview`, устойчивый выбор сервера и
   `effective_outbound`, `apply_changes()` с блокировкой, журнал событий, исправление
   `logs_enabled`/`HUP`, применение у переключателей, `rules_batch`; тесты `tests/php`.
2. **Оболочка + Обзор + Серверы + Настройки (базово):** Preact/htm, layout, навигация,
   компоненты, `servers`/`add_link`/`ping_servers`/`server_probe`; `legacy.php` рядом.
3. **Маршруты:** сервисы, свои правила, `route_explain`.
4. **Диагностика:** события, соединения, проверка сайта, сырые логи, переключатели.
5. **Устройства + WireGuard + мастер + доводка доступности;** чек-лист паритета;
   удаление `legacy.php` — в следующем релизе.

Каждый этап — рабочее состояние, которое можно выложить на роутер.
